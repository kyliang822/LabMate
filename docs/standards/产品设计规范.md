## 产品设计规范

### PROD-01 统一术语与状态文案

| 面向用户 | 接口或数据字段                  | 使用边界             |
| ---- | ------------------------ | ---------------- |
| 实验室  | lab_id                   | 权限与数据范围的归属单位     |
| 设备   | device_id                | 可预约、可关联资料和工单的对象  |
| 资料   | material_id              | 设备手册、使用规定、常见故障案例 |
| 切片   | chunk_id、chunk_index     | 资料解析后的检索单位       |
| 出处   | citations                | 回答所依据的资料片段及定位信息  |
| 预约   | reservation_id           | 明确设备和起止时间的使用安排   |
| 报修草稿 | draft_id，kind=work_order | 尚未提交，不是正式工单      |
| 工单   | work_order_id            | 已确认提交的故障报修记录     |
| 异步任务 | task_id                  | 资料处理任务，不与工单混称    |

工单状态统一显示“待处理、处理中、已解决、已关闭”；预约状态统一显示“有效、已取消”。“已结束”可由时间推导，不作为可手动修改的预约状态。

**检查判据：** 同一页面及接口说明中同一概念使用同一名称；草稿页面不显示“报修成功”；取消的预约不显示为有效。

### PROD-02 页面与角色入口

使用者提供登录、设备列表与详情、预约日历、智能会话、我的预约、我的工单页面。管理员在此基础上提供设备管理、资料及处理任务、预约管理、工单处理页面。隐藏入口仅用于展示，权限必须由后端保障。

**检查判据：** 使用者可以完成预约及报修闭环；管理员可以完成接单、处理、解决、关闭闭环；刷新页面后业务结果仍存在。

### PROD-03 关键操作先展示草稿、再确认

创建预约、取消预约、提交报修，均须展示可核对的操作摘要，再通过明确按钮确认。预约摘要包含设备、日期、起止时间；取消摘要包含原预约；报修摘要包含设备、故障现象、已做排查。缺失必要字段时先补齐。

自然语言请求只生成草稿，不能视为提交授权。草稿修改后须重新确认；重复点击时禁用按钮并复用同一幂等键。表单和会话入口遵守相同规则。

**检查判据：** 草稿生成后数据库中不存在对应正式记录；点击确认后仅产生一次结果；字段修改或确认过期后旧确认不能执行。

### PROD-04 页面状态可恢复

设备列表、预约提交、资料上传、任务处理、SSE 会话均须区分加载中、空结果、成功、失败。冲突提示说明时段已占用并允许重新选择；模型失败不显示“预约成功”；SSE 中断保留已展示内容并标记未完成。

**检查判据：** 分别模拟空设备、预约冲突、文件不支持、模型超时、SSE 断开；用户能识别结果并找到下一步操作，页面无永久加载状态。

### PROD-05 出处与安全提示可见

有依据的操作建议须附出处，能打开有权限的原始资料及对应片段。没有依据时明确说明资料不足。涉及拆机、电气及其他危险操作时引导联系管理员，不生成可照做的高风险步骤。

**检查判据：** 点击出处能核对原文；无资料问题不出现伪造出处；危险操作问题显示联系管理员的路径。
