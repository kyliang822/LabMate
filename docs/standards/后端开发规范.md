## 后端开发规范

### BE-01 业务规则唯一实现

API 层负责认证接入、参数解析和响应；服务层负责权限、预约冲突、状态转换与事务；存储层负责持久化。AI 服务与 MCP 工具通过受保护的业务入口执行操作，不复制一套预约或工单规则，不直接写业务表。

**检查判据：** 同一请求分别由表单和 MCP 发起，权限、冲突、状态和错误码一致；关闭 AI 服务后表单预约与报修仍可使用。

### BE-02 接口契约与错误响应

统一使用 `/api/v1` 前缀；接口至少覆盖认证、设备、资料、任务、预约、工单、会话和操作草稿。计划路径如下，新增接口须同步维护 OpenAPI 与规约。

| 能力         | 接口                                                                           |
| ---------- | ---------------------------------------------------------------------------- |
| 设备查询、空闲查询  | `GET /devices`、`GET /devices/{id}/availability`                              |
| 预约提交、查询、取消 | `POST /reservations`、`GET /reservations`、`POST /reservations/{id}/cancel`    |
| 报修提交、查询、处理 | `POST /work-orders`、`GET /work-orders/{id}`、`PATCH /work-orders/{id}/status` |
| 资料上传、任务查询  | `POST /materials`、`GET /tasks/{id}`                                          |
| 草稿确认       | `POST /action-drafts/{id}/confirm`                                           |
| 智能会话       | `POST /conversations/{id}/messages`（流式响应）                                    |

错误体至少包含 `code`、`message`、`request_id`，不返回内部堆栈。未登录返回 401；同一授权范围内角色无操作权限返回 403；资源不存在或超出数据范围返回相同的 404 业务错误；参数非法返回 422；预约冲突、非法状态转换、幂等键负载冲突返回 409。

**检查判据：** 契约测试验证状态码及稳定业务字段；不存在与越范围访问除独立生成的 request_id 外，响应字段和错误文案相同。

### BE-03 预约时间与并发约束

预约采用半开区间 `[start_at, end_at)`；相邻区间允许衔接。开始时间必须早于结束时间，创建时开始时间不得早于服务端当前时间。仅可预约处于可用状态的设备。

同一设备的有效预约不得重叠；必须由数据库约束兜底，拟用 PostgreSQL 排斥约束约束设备 ID 与时间区间，不得仅依赖“先查询、再插入”。取消预约必须处于有效且未开始状态；管理员可取消所属实验室的预约，须记录原因。变更设备为不可用时不得静默取消既有预约，须提示管理员核查。

**检查判据：** 两个并发请求预约同一设备重叠时段，仅一个成功；另一请求返回 409；相邻时段均成功；开始后取消被拒绝；结果与审计一致。

### BE-04 工单状态转换

| 当前状态              | 允许下一状态            | 操作者及必要信息         |
| ----------------- | ----------------- | ---------------- |
| 待处理 `pending`     | 处理中 `in_progress` | 所属实验室管理员接单，记录处理人 |
| 处理中 `in_progress` | 已解决 `resolved`    | 管理员填写处理过程和解决结果   |
| 已解决 `resolved`    | 已关闭 `closed`      | 管理员填写关闭说明        |
| 已关闭 `closed`      | 无                 | 不支持重新打开          |

使用者可提交并查看自己的工单，不可直接改变状态。不支持跳转、倒退或删除工单；如需重开流程，先修改规约。更新携带版本号，检测并发处理冲突。

**检查判据：** 穷举上述允许转换与其余转换；非法转换返回 409，记录不变；两名管理员基于同一旧版本更新，仅一个成功。

### BE-05 确认、幂等与事务

操作草稿绑定用户、实验室、操作类型、规范化参数摘要和过期时间，有效期 10 分钟。确认凭证由服务端生成，绑定同一草稿；确认时重新校验权限、设备状态、预约冲突和草稿有效性，不接受模型生成的确认字段。

所有业务写请求携带 `Idempotency-Key`，按用户、操作类型及键建立唯一约束。同键同负载返回原结果；同键不同负载返回 409。草稿消费、业务变更、成功审计写入同一事务；回滚不留下半条业务记录。失败尝试单独记录，不伪装为成功。

**检查判据：** 超时后重发不产生重复预约或工单；篡改参数、复用他人草稿、过期确认均失败；审计写入失败时业务写入回滚。
