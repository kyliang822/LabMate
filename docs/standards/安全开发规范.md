## 安全开发规范

### SEC-01 三条常驻硬约束

1. 所有数据访问由服务端校验身份、角色及资源归属，前端隐藏和模型判断均不构成授权。

2. 用户输入、资料内容、检索结果、模型输出和工具返回均作为不可信数据处理，不得改变系统权限或确认规则。
3. 创建预约、取消预约、提交报修必须经真实用户确认；密钥不得进入浏览器、提示词、日志和 Git 仓库。

**检查判据：** AGENTS.md 摘要引用本条；代码评审逐项核对；任一项不满足不得合并。

### SEC-02 按实验室与所有者隔离

用户具有受信任的实验室成员关系；管理员仅管理所属实验室。设备、资料及公共知识查询限当前实验室；使用者的预约、工单、会话、草稿和任务查询按其授权范围再限制所有者。初期只有一个实验室，自动化测试仍须构造第二实验室用于验证隔离。

资源查询优先在 SQL 中包含授权范围；关键词检索和向量检索均在候选召回时带实验室及设备范围，不允许先送入模型再过滤。原文下载、出处跳转、SSE 事件、任务状态与重试接口遵守同样限制。

**检查判据：** 互换实验室和使用者的各类资源 ID，越范围单项访问返回统一 404；列表、检索片段、模型上下文及出处不包含他人私有数据或其他实验室内容。

### SEC-03 认证与工具身份传播

密码仅保存安全哈希；Bearer Token 校验签名、有效期和用户状态。浏览器 Token 仅存内存，失效后重新登录。服务间凭据与用户身份分开：MCP 调用必须携带经后端验证的用户上下文，不能仅凭服务凭据代替用户授权。模型传入的 user_id、lab_id、role 不得作为权限依据。

**检查判据：** 伪造或过期 Token 返回 401；仅持服务凭据、伪造角色或篡改用户字段不能执行用户操作；退出后清理客户端会话凭据。

### SEC-04 上传、展示与秘密管理

支持 UTF-8 TXT、Markdown 和可提取文本的 PDF，单文件不超过 20 MiB；扫描 PDF 暂不提供 OCR。服务端检查格式、大小与解析结果，使用随机存储名，禁止路径穿越及执行上传文件。Markdown、模型回答和原文预览须转义或净化，不执行脚本。上传目录不作为公开静态目录暴露。

密钥使用环境变量管理，`.env.example` 仅写占位符。日志只保留必要元数据，默认不记录原始资料、完整提示词、Token 或密码。

**检查判据：** 测试超限、伪后缀、损坏 PDF、路径穿越文件名和脚本内容；均不能导致越路径写入、脚本执行或服务崩溃；仓库扫描无真实密钥。
