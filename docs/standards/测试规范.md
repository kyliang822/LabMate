## 测试规范

### TEST-01 需求与测试相互可追溯

每项功能规约至少包含正常流程、权限边界和失败场景，并记录对应测试 ID。单元测试覆盖纯规则；集成测试使用真实 PostgreSQL/pgvector 验证约束和检索范围；端到端测试验证用户闭环；AI 评测验证依据、工具选择和安全边界。

**检查判据：** 规约中的 MUST 条款均有测试或可复现的人工检查步骤；数据库并发测试不得以模拟存储替代。

### TEST-02 断言行为与副作用

不得仅断言状态码、非空或列表长度。预约测试须断言具体设备、时间、所有者、有效记录数和审计；检索测试须断言预期来源和禁止出现的来源；失败写操作须断言业务数据未改变。

**检查判据：** 在本地临时移除冲突、权限或状态检查，相关测试应失败；完成检查后恢复代码，不提交破坏性改动。涉及这些规则的变更必须保留此证据。

### TEST-04 统一检查入口

约定 `make check` 依次运行前端类型检查与生产构建、后端静态检查、单元测试、集成测试，以及使用固定模型替身的 AI 契约与安全测试。任一子项失败必须返回非零退出码，不能用跳过数据库测试或吞掉异常得到通过结果。

`make eval-live` 单独执行真实模型固定评测；提示词、模型、技能、检索策略或工具定义变化时必须运行，发版前也必须运行。真实模型不可用时记录阻塞，不能用替身报告替代真实评测。

**检查判据：** 新环境能按 README 执行命令；报告包含提交号、环境、通过/失败数及失败原因；上述命令须实现后才能作为完成证据。
