# LabMate 项目规约入口

## 定位与状态

LabMate 面向实验室设备使用者和管理员，计划整合设备信息、知识库问答、预约、故障排查与报修处理。当前已编写第 8 课异步基础（代理、任务表、提交入口与 outbox），其余功能仍是框架；完整链路尚待数据库验证与消费者集成。本文件为项目上下文与规约编写入口，不表示各功能已经完成，也不表示已完成 OpenSpec CLI 初始化。

## 范围与角色

- 初期一个实验室、少量典型设备，采用演示数据和允许使用的资料；不接入真实硬件控制、自动维修或学校正式业务系统。
- 使用者查询设备和资料，管理自己的预约、报修与会话。
- 管理员管理所属实验室设备、资料、预约及工单。服务端执行身份、角色与数据范围校验；测试仍须构造第二实验室验证隔离。

## 待细化的功能规约

以下均为计划需求，须在实现前补充可验收的功能规约与测试映射：

| 能力           | 主要验收边界                    | 测试规范中的关联场景          |
| ------------ | ------------------------- | ------------------- |
| 登录与权限、设备管理   | 未登录拒绝、跨实验室和所有者隔离          | T01、T02             |
| 预约查询、创建与取消   | 草稿确认、冲突、相邻时间、幂等、事务审计      | T03、T04、T05         |
| 故障排查、报修与工单处理 | 报修先确认、合法状态转换、危险问题转管理员     | T05、T06、T13         |
| 资料与可追溯流式问答   | 授权检索、有效出处、无依据及失败提示、SSE 中断 | T02、T07、T08、T09、T13 |
| 异步任务与 MCP 工具 | 任务状态、失败重试、参数及身份校验、写入边界    | T10、T11             |
| 部署与持久化       | 重启、备份恢复、基础业务不依赖模型可用性      | T12                 |

三项计划技能为设备使用指导、故障分步排查、报修信息整理。工具及业务契约以相关开发规范为依据。

## 架构与技术决策

计划采用 Vue 3 / TypeScript / Element Plus、FastAPI、PostgreSQL / pgvector、独立 AI 与 MCP 服务、Redis / Celery 和 Docker Compose。API 与 MCP 复用同一业务规则；预约冲突、权限和工单状态不能交由模型裁决。

待决事项：现有前端 `.tsx` 占位文件与计划 Vue 3 技术栈不一致，首次前端实现前须记录选择并统一配置。第 8 课基础已记录 Python 依赖和 Compose 配置，尚无已验证部署环境。

## 规约编写与变更流程

每个功能或行为变更须在 `openspec/` 内形成独立文档，至少记录：问题、目标、非目标、受影响规范编号、角色与权限、接口与数据约束、正常场景、边界与失败场景、验收标准、测试 ID 和待决事项。具体目录组织及 CLI 使用方式待工具初始化时确定，不宣称已有 CLI 工作流。

每条 MUST 要求关联自动化测试或可复现的人工验证步骤。涉及权限、数据、模型和工具行为的调整，先修改规约并记录决策，再修改实现和测试。验证证据注明环境、版本、结果及未完成项。
