# Lesson08 消费者、任务查询与审核机制

问题：只有提交和 outbox 转发，无消费者、状态查询与工程审核证据。
目标：实现资料解析/切分/外部嵌入/原子发布、版本模型、任务查询/手动重试/安全恢复、管理员任务页面、七类审核规则/七维评审模板与扫描入口。
非目标：本次不将登录、预约、工单、问答/MCP 占位改称已完成；不替人签署交叉评审；不声称真实依赖或真实模型未运行的验收通过；不直接推送、合并或发布。
规范：BE-01/02/05、DATA-01～04、SEC-01～04、PROD-01/02/04、OPS-01/02、TEST-01～04、REVIEW-01～05。

## 设计决定
- PostgreSQL 为业务事实来源。保留旧 async_tasks.material_id 对版本行 ID 的含义，新增 material_versions.material_id 表示逻辑资料 ID；不改历史迁移。
- 消费者持有 task_id 对应的数据库 session advisory lock，重复执行只能单持有者领取。恢复程序也先取得同一锁，不能重置运行中的 worker。连接失效后旧执行者不得重新连接写结果。
- 失败瞬时重试通过同事务重新激活 outbox 和 available_at 实现；不依赖 Celery 结果后端，自动重试最多两次。永久失败及耗尽尝试写入持久失败表（应用死信），人工重试独立记录命令幂等与 cycle。
- READY、切片和资料 current_version 指针在同一事务发布。较旧版本稍后完成不得覆盖较新版本。处理中结果不进入可检索视图。
- 配置真实 OpenAI 兼容嵌入接口；无配置时明确失败，不在业务路径生成假向量。维度与模型标识写入版本元数据。
- 管理员页面为异步模块演示入口，使用内存中的演示令牌，不伪装完整登录系统。正式前端统一采用 Vue 3。
- 保留 make check 的全项目阻塞语义。新增模块门禁和扫描；新 CI 运行无需数据库的检查，数据库门禁仍显式要求真实环境。
